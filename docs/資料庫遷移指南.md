# 資料庫遷移與環境建置指南

本文件記錄專案本機環境變數配置、Supabase PostgreSQL 連線規範，以及 Alembic 資料庫遷移（Migration）的常用指令與作業流程。

---

## 一、本機環境準備（.env）

本專案使用 `python-dotenv` 管理環境變數，資料庫連線字串僅自環境變數 `DATABASE_URL` 讀取，絕不在程式碼中寫入任何連線帳密。

> [!IMPORTANT]
> **本機必須先備妥 `.env` 檔案**：
> 請參考專案根目錄的 [.env.example](file:///Users/keoinn/Desktop/ledger-api/.env.example)，在專案根目錄建立 `.env` 檔案（該檔案已於 [.gitignore](file:///Users/keoinn/Desktop/ledger-api/.gitignore) 排除，絕對不會被提交至版本控制）：
> ```env
> DATABASE_URL=postgresql://postgres.<project-ref>:<password>@aws-0-<region>.pooler.supabase.com:6543/postgres
> ```

### 連線設定注意事項：
1. **Supabase 連線協定**：
   - 若自 Supabase 複製的字串為 `postgres://...`，系統（`app.py` 與 `migrations/env.py`）已內建自動轉換邏輯，會自動標準化為 `postgresql://...` 以相容 SQLAlchemy 2.0+。
   - 建議優先使用 Supabase 的 **Transaction Pooler（連接埠 6543）** 或 **Session Pooler（連接埠 5432）**。
2. **無環境變數之防呆機制**：
   - 若 `DATABASE_URL` 未設定或為空值，應用程式（`app.py`）與 Alembic 在啟動時會立即拋出 `RuntimeError` 終止程序，絕不連線至本機 Localhost 或預設資料庫。

## 二、Alembic 遷移指令速查表

當建立或修改資料表 Model 後，請使用以下 Alembic 遷移指令進行版本追蹤與套用。
**所有遷移指令需由開發者在專案根目錄之本機終端機親自執行**。

| 操作情境 | 遷移指令（macOS / Linux） | 遷移指令（Windows PowerShell） |
| :--- | :--- | :--- |
| **自動比對 Model 產生遷移檔** | `./.venv/bin/alembic revision --autogenerate -m "描述名稱"` | `.\.venv\Scripts\alembic revision --autogenerate -m "描述名稱"` |
| **手動建立空白遷移檔** | `./.venv/bin/alembic revision -m "描述名稱"` | `.\.venv\Scripts\alembic revision -m "描述名稱"` |
| **執行遷移（套用至最新版本）** | `./.venv/bin/alembic upgrade head` | `.\.venv\Scripts\alembic upgrade head` |
| **回滾上一個版本** | `./.venv/bin/alembic downgrade -1` | `.\.venv\Scripts\alembic downgrade -1` |
| **查看目前資料庫版本標籤** | `./.venv/bin/alembic current` | `.\.venv\Scripts\alembic current` |
| **查看歷史遷移軌跡** | `./.venv/bin/alembic history --verbose` | `.\.venv\Scripts\alembic history --verbose` |
| **比對目前狀態是否需要產生遷移** | `./.venv/bin/alembic check` | `.\.venv\Scripts\alembic check` |

> [!NOTE]
> 產生的遷移版本檔案將存放於 [migrations/versions/](file:///Users/keoinn/Desktop/ledger-api/migrations/versions/) 目錄下。

## 三、標準遷移工作流程

當要新增或調整資料表結構時，請遵循以下步驟：

1. **定義或調整 Model**：於專案中撰寫繼承自 `db.Model` 的資料表結構。
2. **自動產生遷移腳本**：
   ```bash
   ./.venv/bin/alembic revision --autogenerate -m "create_initial_tables"
   ```
3. **檢視產生的遷移檔**：
   開啟 `migrations/versions/<revision_id>_create_initial_tables.py`，確認 `upgrade()` 與 `downgrade()` 函式內容符合預期。
4. **套用遷移至 Supabase**：
   ```bash
   ./.venv/bin/alembic upgrade head
   ```
5. **確認版本**：
   ```bash
   ./.venv/bin/alembic current
   ```

## 四、安全約束與查詢準則

> [!CAUTION]
> **嚴禁 SQL 注入（SQL Injection）**：
> 後續撰寫資料庫操作時，所有查詢參數均會嚴格透過 SQLAlchemy 參數化綁定（Parameterized Queries / ORM），**嚴禁將任何外部輸入或變數拼進 SQL 字串**。

- **正確做法（ORM 查詢）**：
  ```python
  item = db.session.execute(
      db.select(Item).where(Item.id == item_id)
  ).scalar_one_or_none()
  ```
- **正確做法（原生 SQL 參數化綁定）**：
  ```python
  result = db.session.execute(
      db.text("SELECT * FROM items WHERE category = :category"),
      {"category": category_input}
  )
  ```
- **嚴禁行為（字串拼接）**：
  ```python
  # 絕對禁止
  db.session.execute(f"SELECT * FROM items WHERE category = '{category_input}'")
  ```
